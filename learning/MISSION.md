# Mission: Matt Pocock's agent skills

> **Draft.** Written from Nathan's first request, before any interview. `/teach`: in the first session, confirm or rewrite this with Nathan before teaching anything, and record the result as a learning record.

## Why
Use these skills as my default way of working with coding agents, so features I build with an agent come out aligned with what I meant, tested at the right seams, and leave the codebase deeper rather than muddier.

## Success looks like
- Given any situation (vague request, hard bug, pile of issues, foggy project, muddy module), I pick the right skill or flow without asking `/ask-matt`.
- I've run the main flow end to end, `/grill-with-docs` to `/retro`, on a real feature at work.
- I stop an agent that theorises about a bug before it has a red feedback loop.
- I make phase-boundary calls (continue, `/clear`, `/handoff`, subagent, `/compact`) deliberately and can defend each.
- I can argue for or against a refactor in deep-module vocabulary.
- I've adapted at least one skill, or written my own, because the defaults didn't fit.

## Constraints
- Senior engineer, about ten years in. Python and JavaScript daily; tolerates TypeScript.
- Harness: Claude Code.
- Time per week: unknown. Ask.

## Out of scope
- Skills in `../skills/in-progress/`, `../skills/misc/` and `../skills/deprecated/`, unless I ask.
